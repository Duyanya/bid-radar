一、背景与目标

1.1 业务背景

中国移动、中国电信、中国联通三大运营商的招标公告分散在三个独立官网，各自有不同的检索方式、页面结构和防爬机制。投标人员日常面临三个问题：

  1. 信息分散 —— 要反复登录三个网站手工翻查，效率低
  2. 噪声太大 —— 运营商招标中大量是维保、设备采购、安全测评、房租劳务，与网络域建设无关，人工筛选耗时
  3. 信息会消失 —— 公告下架后原页面就打不开了，事后无法回溯

1.2 系统目标

建设一个自动化的招标信息聚合系统，实现：

  • 自动采集：每日定时抓取三家运营商招标公告，无需人工值守
  • 精准过滤：只保留省公司/集团总部的网络域建设项目，无关数据不入库
  • 永久留存：公告入库即存档，官网下架后本地仍可查，不丢历史
  • 结构化输出：金额、建设内容等字段经识别归纳后结构化存储，可直接用于分析决策

1.3 核心设计原则

原则 说明
数据永久性优先 入库即持久化 + 本地快照。官网查不到只标「已下架存档」，绝不删除
宁缺毋滥 识别不到就留空显示 —，绝不编造金额或厂商
识别而非复制 金额输出纯数字，建设内容归纳提炼，不照抄公告原文
过滤前置 先过滤后抽详情，减少请求量，降低被封 IP 风险

2.3 字段识别与规范化

这是系统的核心难点，要求识别归纳而非复制原文。

字段 要求 反例（禁止） 正例（要求）
招标金额 纯数字，单位元，不带任何文字 384 万元、限价为2,394,038.01元 3840000
建设内容 正文「采购内容 / 建设内容 / 招标范围」段逐句筛选提炼：先剥编号与版式词，再按「网域词 + 建设动作词」双条件挑句，剔除资格/工期/报价/人天表等条款，按原文顺序合成一段（≤300 字）；正文无可用内容时回退标题主干 整段复制「本项目为集中招标项目。本项目采购2026年至2028年有线接入网迁改整治服务…」或把「标包1 驻地网施工 项 152」表格行当建设内容 2026年业务编排中心围绕"专线业务开通、专线业务开通数据透明化"二个方面开展能力建设，新增任务管理等
建设内容（正文有建设动作时） 正文「采购内容 / 建设内容」段写明网元上收、业务迁移、设备搬迁等建设动作时，按原文保留，可到 160 字；保留设备型号与厂家名（HSS/UDM/中兴/华为不构成剔除理由） 将「3套中兴HSS及1套华为HSS上收至UDM（其中东莞科技园1套华为HSS因机房搬迁需实施3/4G业务迁移至5G网元UDM…）」压成标题截断的「广东核心网组网设备升级改造专项工程核心网集成服务」 与原文一致
中选厂商 只取企业名称，不含数量/份额 中标人数量1个 浪潮通信信息系统有限公司

金额识别逻辑：正则匹配「限价/预算/金额/总价 + 数字 + 元/万元/亿元」，统一换算为元，过滤低于 1000 或高于 1000 亿的误匹配值。

建设内容归纳逻辑（正文优先，逐句筛选提炼）：

  1. 定位建设段：以「采购内容 / 建设内容 / 招标范围 / 采购范围 / 项目概况 / 工程概况 / 建设规模 / 服务内容」为起点；遇到「投标人资格 / 评审办法 / 递交 / 开标 / 联系方式 / 序号·产品名称 / 标包1 / 服务类别 / 保修期」等终止标记即截断，表格起点之后一律不读。
  2. 接行 + 切句：先把被 PDF/HTML 折断的行接回整句，再按 。！？；和换行切分。
  3. 逐句筛选（打分）：候选句必须同时含网域词（网 / 专线 / 切片 / 基站 / 核心网 / 网元 / 承载 / 传输 / 接入 / 中台 / 编排 / 5G / CMNET / DCN…）与建设动作词（建设 / 研发 / 开发 / 扩容 / 升级 / 改造 / 迁移 / 上收 / 纳管 / 开通 / 采集 / 集成 / 构建 / 支撑 / 实现 / 具备…）；剔除资格、业绩、保证金、时间地点、报价、工期、验收、保修等条款句，以及人天表、数量表碎片。
  4. 先剥版式词再判定：1.2.1、（一）、一、、包括：、本主要、项目名称： 这类编号与标签先剥离，不因「以编号开头」整句丢弃。
  5. 合并提炼：按原文顺序取前若干句用「；」合成一段，总长 ≤ 300 字；与标题重复的句子丢弃。
  6. 兜底：正文提炼不出（电信正文 401 不可见），或提炼结果不比原值信息量更大时，回退标题主干提炼；仍识别不到就留空，不硬编。
  7. 列举特例优先：正文出现「一是…二是…三是…」（≥3 段连续列举）时整段原样保留，不受 300 字与打分限制。

3.6 关键实现难点

难点 问题现象 解决方案
WAF 拦截 直接 curl/requests 返回 412 或空 必须 Playwright + --disable-blink-features=AutomationControlled
分页失效 移动翻页始终返回第一页 分页参数是 current/size，不是 pageNum/pageSize
正文是 PDF noticeContent 字段是乱码 base64 解码后用 pypdf 提取文字
电信限流 第 3 页起重复返回第一页 限制每轮 6 次请求 + 5~8 秒间隔 + seen_ids 去重，靠每日累积
排除词误杀 正文必含「采购代理机构：XX咨询设计研究院」，用正文判断导致全量误杀（25 条杀到只剩 1 条） 排除词只对标题生效
机房项目漏网 「机房等保整改」被「等保」救活 机房判定提到所有规则之前（第 1 步）
缩写误匹配 AIDC 被 IDC 命中 英文缩写改用词边界匹配 \b
厂商名被切断 PDF 硬换行把「中选\n人」切断，抽到采购人而非中选人 换行归一化 + 上下文排除采购人 + 贪婪匹配机构后缀
移动详情页打不开 hash 路由直达只渲染页脚 已改为提示「快照更可靠」，快照有完整正文
